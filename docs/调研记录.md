## 已直接核实

以下结论来自用户提供的工单和本地现有代码，不依赖失败的外部调研：

1. 产品主流程是“选素材 → 选发布账号 → 编辑正文 → 选背景 → 调卡片 → 生成文案 → 下载 PNG”。
2. 推文来源与发布账号必须解耦。
3. 当前本地工具链已经存在：
   - `gary-x-post-crawler`：输出帖子正文、链接、日期、媒体和互动指标 CSV，并提供原创校验字段。
   - `gary-x-analytics/analyze_csv.py`：按 CSV 字段区分纯文字、图文候选和排除项。
   - `gary-x-analytics/screenshot_posts.mjs`：纯文字帖截图。
   - `gary-x-analytics/classify_pure_text_screenshots.py`：纯文字分类任务与目录整理。
   - `gary-x-analytics/compose_pure_text_materials.py`：1080 × 1440 风景背景合成。
   - `gary-x-analytics/merge_collection.py`：生成网页可适配的 `collection_manifest.json`。
4. 现有风景合成规范使用 1080 × 1440 画布，截图等比缩放、默认中上位置，不裁切截图。
5. Cookie / storage state 属于采集器凭据，不能进入网页、导入文件或项目仓库。

## 当前实现采用的复刻判断

这些属于工程判断，不冒充参考站实证：

- React 状态负责推文、账号、权限演示和卡片参数。
- Pointer Events 负责卡片拖动。
- File API / 对象 URL 负责本地背景预览。
- Clipboard API 负责复制发布文案。
- Canvas API 负责 1080 × 1440 PNG；这样比 DOM 截图更容易保证尺寸和数据一致。
- 正式团队权限必须由服务端返回可用账号列表并在接口层再次校验。
- 网络背景正式版应先进入同源对象存储，避免 Canvas 被跨域图片污染。
